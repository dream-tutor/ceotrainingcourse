# 데일카네기 두 번째 사이트 (site2)

첫 사이트(`../site`, leadershipcourse.co.kr)와 **같은 데이터를 쓰되 문장과 디자인은 다른** 두 번째 홍보 사이트.
460개 페이지를 정적으로 생성한다.

## 쓰는 법

```bash
node build.js        # docs/ 에 460개 페이지 생성
node serve.js        # http://localhost:4173 미리보기 (PORT 로 바꿀 수 있다)
node make-og.js      # 공유 카드(assets/og.png) 다시 뽑기 — src/og.html 을 고쳤을 때만
```

## 배포 전에 반드시 할 것

**`build.js` 상단 `SITE.BASE_URL`에 도메인을 넣어야 한다.** 비어 있으면
전 페이지가 `noindex`로 나가고 `canonical`·`sitemap.xml`·`robots.txt`·빵부스러기 구조화 데이터가 빠진다.
(도메인이 정해지기 전에 검색엔진에 잡히지 않게 하려고 일부러 이렇게 두었다. 빌드할 때마다 경고가 뜬다.)

## 페이지 구성 (460개)

| 묶음 | 수 | 파일 |
|---|---|---|
| 단독 | 11 | index, courses, schedule, regions, concerns, topics, corporate, reviews, about, faq, 404 |
| 과정 상세 | 9 | `course-<key>.html` |
| 지역 | 24 | `region-<slug>.html` |
| 고민별 | 12 | `concern-<slug>.html` |
| 검색 주제 허브 | 20 | `topic-<slug>.html` |
| 지역 × 주제 | 384 | `<region>-<topic>.html` (조합 주제 16 × 지역 24) |

검색 주제는 2단이다. 1단 허브(`topic-*.html`)가 전국 기준으로 그 키워드를 설명하고,
2단 조합(`<region>-<topic>.html`)이 같은 키워드를 그 지역의 실제 데이터와 붙인다.

**조합 페이지가 얇아지지 않게 하는 것이 이 구조의 핵심이다.** 지역마다 실제로 다른 값
(개설 이력, 최고 기수 번호, 강의장, 지사 관할 지역, 동문회 활동, 수강료 범위)을
`regionFacts()`가 문장으로 만들어 본문에 싣는다. 이것을 빼면 같은 주제의 24개 지역 페이지가
서로 베낀 문서가 되어 검색엔진이 doorway page로 본다.

현재 수치 (`node test-similar.js`로 확인):
- 평균 본문 2,080자
- 같은 주제 다른 지역 유사도 0.586 / 같은 지역 다른 주제 0.477
- 80% 넘는 쌍 0개 (최대 0.767)

주제를 더 늘릴 때는 이 수치를 먼저 확인할 것. 같은 주제 다른 지역이 0.7을 넘으면
주제를 늘리지 말고 지역 데이터를 더 싣는 쪽을 먼저 봐야 한다.

## 첫 사이트와 공유하는 것

일정·지역·과정·후기는 `../site/data.js`, 추천의 글은 `../site/ceo-content.js`를 읽는다.
**개강 일정이 바뀌면 `../site/data.js`의 `SCHEDULE`만 고치고 두 폴더에서 각각 `node build.js`를 돌린다.**

상담 폼은 첫 사이트와 같은 GAS 시트로 들어간다. 입력 항목 이름(`이름`·`연락처`·`소속`·`직급`·`관심과정`·`지역`·`문의내용`)을 바꾸면 시트가 깨진다.

**문장은 공유하지 않는다.** 같은 자료를 쓰되 문구는 새로 썼다(중복 콘텐츠 방지).
예외는 인용문 — 추천의 글, 수강 후기, 정규 커리큘럼 모듈명은 양쪽이 같아도 된다.
겹치는지 확인하려면 두 사이트의 한글 문장 교집합을 비교하면 된다.

## 날짜 규칙 (건드리기 전에 읽을 것)

데이터의 개강·수료일은 `"MM.DD"`라 연도가 없다. `schedDate()`는 작년·올해·내년 중
기준일에 **가장 가까운 해**를 고른다. 수료일은 개강일을 기준으로 다시 읽고,
그래도 개강일보다 앞서면 이듬해로 본다. 로직은 `lib-dates.js` 한 곳에만 둔다.

달 번호끼리 빼서 비교하는 방식으로 바꾸면 **10월 개강 + 1월 수료** 조합에서 한 해가 어긋나
아직 개강도 안 한 기수가 '종료'로 찍힌다. 실제로 두 번 그렇게 깨졌다.
날짜 로직을 고쳤으면 `node test-dates.js`를 돌릴 것.

## 톤 규칙

AI 말투와 과장 표현을 쓰지 않는다. "가장/최고의/반드시/정말" 같은 말과 근거 없는 효과 약속을 빼고,
과정을 설명하기보다 고객이 지금 겪는 문제를 설명한다. 교육으로 풀리지 않는 부분은 풀리지 않는다고 적는다.

사이트가 자기가 한 일을 해설하지 않는다. "지역별 페이지를 따로 두었습니다", "N가지 주제로 나눠 두었습니다",
"지난 기수도 함께 두어 보실 수 있게 했습니다" 같은 문장은 쓰지 않는다. 방문자가 보게 될 것만 쓰고,
그것을 어떻게 배치했는지는 쓰지 않는다. 특히 조합 페이지에서 구조를 설명하면 검색 유입용 페이지라는 것을
그대로 알려 주는 꼴이 된다.

```bash
grep -on "(나눠 두|따로 두|함께 두|모아 두|정리했습니다|실었습니다|게 했습니다)" build.js content*.js
```

## 전 사이트 공통 규칙 (상위 CLAUDE.md)

- **전화번호를 화면 글자로 내보내지 않는다.** `tel:` href·`aria-label`·JSON-LD `telephone` 만 허용하고,
  버튼·본문에는 "전화 상담" 같은 글자 라벨만 쓴다. 전화 진입점도 **우하단 플로팅 버튼 하나뿐**이다.
- **일정은 개강일만 적고 수료일은 적지 않는다.** `close` 는 '종료' 상태를 계산하는 데만 쓴다.
  예외는 2일 과정(DYLP) 하나로, 카드에 `11.12~11.13 · 2일` 처럼 교육일을 적고 '매주'를 붙이지 않는다.
- **사진은 `../site/assets` 의 얼굴 처리된 것만** 쓴다. `교육과정사진/` 원본은 쓰지 않는다.
  사람 이름·전화번호가 읽히는 사진도 쓰지 않는다(수료증 사진 `class-004.jpg` 를 그래서 뺐다).
- 개인정보 동의 체크는 폼당 하나, 라벨은 짧게, 상세는 접힌 `<details>` 안에.

앞의 두 가지는 `node test-pages.js` 가 `visibleTel`·`telLinks` 로 검사한다.

## 빌드 후 점검

```bash
node build.js && node test-dates.js && node test-pages.js && node test-console.js
```

| 스크립트 | 보는 것 |
|---|---|
| `test-dates.js` | 개강·수료일 연도 해석. 빌드 날짜를 24개로 바꿔 가며 미개강 기수가 '종료'로 찍히지 않는지 |
| `test-pages.js` | 깨진 내부 링크·이미지, id 중복, 페이지당 h1 개수, 템플릿 자국(`undefined`·`{R}`), `#앵커` 유효성, title·description·h1이 페이지마다 다른지, title 60자 초과, 화면 글자에 전화번호 노출, 페이지당 tel 링크 2개 이상 |
| `test-console.js` | 460개 페이지를 헤드리스 크롬으로 열어 콘솔 오류·예외 수집 (크롬이 설치돼 있어야 한다). 60개마다 크롬을 새로 띄운다 — 탭 하나로 다 돌면 `ERR_INSUFFICIENT_RESOURCES` 가 난다 |
| `test-similar.js` | 지역×주제 조합 페이지끼리 얼마나 겹치는지 (위 '페이지 구성' 참고) |

마지막 것이 특히 중요하다. 빌드는 멀쩡히 통과하는데 브라우저에서만 터지는 오류가 있고,
실제로 모든 과정·지역 페이지(33개)에서 JS가 통째로 죽던 것을 이 검사로 잡았다.
